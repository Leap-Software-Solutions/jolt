# Component guidelines

Jolt components wrap bits-ui primitives, so consumers get the behaviour without the parts-and-portals boilerplate. The common case should be one import and one element.

## Combined by default

Most components own their trigger, portal, content, and focus management:

```svelte
<script lang="ts">
	import { Dialog, Select } from '@leap-online/jolt';

	let status = $state('active');
	let open = $state(false);
</script>

<Select
	items={[
		{ value: 'active', label: 'Active' },
		{ value: 'draft', label: 'Draft' },
	]}
	bind:value={status}
	ariaLabel="Status"
/>

<Dialog bind:open title="Delete asset" description="This cannot be undone.">
	<p>...</p>
</Dialog>
```

State is controlled with `bind:` props such as `bind:open`, `bind:value`, and `bind:checked`. Event callbacks (`onValueChange`, `onOpenChange`, `onCheckedChange`) remain available when you need to react to changes.

## Snippets

Content is customised with snippets instead of exported parts. Default body content uses `children`; named snippets are reserved for chrome and repeated items:

- `trigger` — render a trigger element with the props supplied by the primitive.
- `item` — render one item in a list, menu, or combobox.
- `selected` — render the selected value inside a trigger.
- `empty` — render the empty state for a list or search result.
- `header` / `footer` — render a content section.
- `children` — render the main body or panel content.
- `content` — render a tab or accordion item body.

```svelte
<Combobox
	items={engineers}
	bind:value
	getKey={(engineer) => engineer.id}
	getLabel={(engineer) => engineer.name}
	placeholder="Assign engineer"
	ariaLabel="Assign engineer"
>
	{#snippet item(engineer)}
		<span>{engineer.name}</span>
	{/snippet}

	{#snippet empty()}
		No engineers match that search.
	{/snippet}
</Combobox>
```

## Content model

Use a prop when the component owns a fixed piece of copy, `children` when the caller needs arbitrary composition, and typed arrays for repeatable data. Named snippets are for trigger, header, footer, empty state, and item renderers.

```svelte
<Badge label="Active" />

<Badge count={12} />
<Badge count={128} maxCount={99} />

<Alert title="Could not save" description="Check your connection and try again." />

<Dialog title="Delete asset" description="This cannot be undone.">
	<p>Any content can go here.</p>
</Dialog>

<Tabs items={tabs} bind:value>
	{#snippet content(item)}
		<p>{item.label} panel</p>
	{/snippet}
</Tabs>
```

The current components follow this split:

- Fixed copy: `Badge`, `Alert`, `Card` header, `Dialog`, `Sheet`, `ConfirmDialog`, `PageHeader`, `EmptyState`, fields, `Checkbox`, `Switch`, and progress/slider labels.
- Arbitrary composition: `Button`, `Toggle`, `Label`, `ScrollArea`, `Card` body, dialog/sheet bodies, `HoverCard`, `Popover`, and `AppShell` content.
- Typed data: the list components below, plus `Select`, `Combobox`, `MultiSelect`, `SplitButton`, `Table`, `DataTable`, `TreeView`, `AttachmentList`, and `Lightbox`.

`Popover` uses `children` for its content, matching Dialog, Sheet, and HoverCard. Tooltip keeps its `text` prop for the common case and an optional custom `content` snippet.

## Lists and item arrays

`Select`, `Combobox`, `MultiSelect`, `SplitButton`, `NavigationMenu`, `Menubar`, `DropdownMenu`, `ContextMenu`, `Tabs`, `Accordion`, `RadioGroup`, `ToggleGroup`, `Breadcrumb`, and `Pagination` take typed item arrays or configuration props. This keeps the markup small and makes keyboard navigation, typeahead, and selection state live in one place.

- `Select` items are `{ value, label, disabled? }`. Pass `getKey` when values are objects.
- `Combobox` takes your own data array plus `getKey` and `getLabel`. Set `creatable` and provide `createItem` to turn typed text into a value; the create row is hidden when the query exactly matches an existing label.
- `MultiSelect` uses the same item array plus a bindable `values` array and renders selected items as removable chips.
- `ContextMenu` uses the same entry union as `DropdownMenu` and opens on the trigger's context-menu event.
- `NavigationMenu` items either provide a `content` snippet for a panel or an `href` for a direct link; `value` controls the open panel.
- `Menubar` takes typed menu entries in a horizontal bar; its menus support separators, groups, submenus, checkboxes, radio groups, shortcuts, and disabled items.
- `DropdownMenu` uses a discriminated union over `item`, `separator`, `group`, `submenu`, `checkbox`, and `radio`. Items with no `type` are regular actions.
- `Tabs` items are `{ value, label, icon?, disabled? }`; the `content` snippet receives the item.
- `Accordion` items are `{ value, title, content?, icon?, disabled? }`; the `trigger` and `content` snippets receive the item.
- `RadioGroup` items are `{ value, label, description?, icon?, disabled? }`.
- `ToggleGroup` items are `{ value, label?, ariaLabel?, icon?, disabled? }`.
- `SplitButton` takes a label, a primary action, and typed menu entries for the adjacent chevron menu.
- `Breadcrumb` items are `{ label, href?, icon?, current? }`; set `maxItems` to collapse the middle of long paths into an overflow menu.
- `Pagination` takes `count`, `perPage`, `page`, and `siblingCount`; page changes use `bind:page`.

Generic components are inferred at the call site:

```svelte
<Combobox
	items={engineers}
	bind:value
	getKey={(engineer) => engineer.id}
	getLabel={(engineer) => engineer.name}
	ariaLabel="Assign engineer"
/>
```

For free-text assignment, enable `creatable`. `createItem` receives the trimmed query and returns the value to select, or `undefined` to reject creation. A created value stays selected even before the parent adds it to `items`; add it to the list when it should become searchable.

```svelte
<Combobox
	items={engineers}
	bind:value
	getKey={(person) => person.id}
	getLabel={(person) => person.name}
	creatable
	createItem={(name) => ({ id: `invite:${name.toLowerCase()}`, name, pending: true })}
	createLabel={(query) => `Invite “${query}”`}
	ariaLabel="Assign action item"
/>
```

## Utilities

`formatRelativeTime`, `formatDuration`, `formatBytes`, and `formatNumber` are exported from the package root for values rendered outside a component.

```svelte
<script lang="ts">
	import { formatBytes, formatDuration, formatRelativeTime } from '@leap-online/jolt';
</script>

<p>Updated {formatRelativeTime(job.updatedAt)}</p>
<p>{formatDuration(job.durationSeconds)} · {formatBytes(job.sizeBytes)}</p>
```

`formatRelativeTime` accepts a `Date`, ISO string, or timestamp and returns a stable English label such as `3 hours ago`, `yesterday`, or `in 2 days`. It renders `just now` under 45 seconds and `Invalid date` for unparseable values.

`TimeAgo` renders the same relative label as a passive `<time>` element. The absolute timestamp is available through the native `title` tooltip, the `datetime` attribute, and the accessible name; the visible label is not a focus target.

```svelte
<TimeAgo date={job.updatedAt} />
```

The label refreshes on a minute interval. Invalid timestamps render as `Invalid date` without removing the row.

`DescriptionList` renders label/value metadata as a semantic description list. It supports horizontal and stacked layouts, skeleton rows, a custom value snippet, and an optional copy control per row.

```svelte
<DescriptionList
	items={[
		{ label: 'Endpoint', value: 'https://api.example.com/v1', copyable: true },
		{ label: 'Region', value: 'eu-west-1' },
	]}
/>
```

Use `copyValue` when the visible value is rendered through the `value` snippet but the copied text should stay plain.

`FeedItem` is a compact row for activity and result lists. It supports leading and trailing snippets, a title and meta line, an unread marker, and a whole-row activation target that remains keyboard-operable. Trailing controls stay outside the activation target.

```svelte
<FeedItem title="Deployment completed" meta="Production · 3 minutes ago" onActivate={openRun}>
	{#snippet leading()}
		<Avatar alt="Ada Lovelace" initials="AL" size="sm" />
	{/snippet}
	{#snippet trailing()}
		<Badge label="Ready" variant="secondary" />
	{/snippet}
</FeedItem>
```

Use `href` for navigation or `onActivate` for in-page actions. The trailing slot is the place for badges, timestamps, or a separate action.

`SeverityDot` is a compact severity indicator for dense rows and table cells. It pairs a semantic tone with a distinct glyph so severity is not communicated by colour alone. The icon is labelled for assistive technology; set `showLabel` when the column has room for the visible label.

```svelte
<SeverityDot severity="critical" />
<SeverityDot severity="high" showLabel />
```

## Fields

The field wrappers combine a visible label, optional hint, error text, and the control's ARIA wiring:

```svelte
<script lang="ts">
	import { CheckboxField, SelectField, TextField } from '@leap-online/jolt';

	let name = $state('');
	let status = $state('active');
	let accepted = $state(false);
</script>

<TextField label="Full name" bind:value={name} required />
<SelectField label="Status" items={statuses} bind:value={status} />
<CheckboxField label="Accept the terms" bind:checked={accepted} />
```

`TextField`, `TextareaField`, `SelectField`, and `CheckboxField` generate their own ids. The error text becomes `role="alert"` and is connected to the control with `aria-describedby`; the control gets `aria-invalid` while the error is present. Prefer these wrappers over rebuilding label and description markup by hand.

`FileUpload` handles drag-and-drop selection, file size validation, and removable attachment chips. It is a regular form control, not a chat-specific component. Image, Markdown, text, and source files preview in the shared lightbox; local object URLs provide the download action.

`TagsInput` is the free-form counterpart to `MultiSelect`: it accepts arbitrary strings, splits pasted lists, supports removable chips, and can validate, normalise, deduplicate, and limit values. Enter always adds the current text; configure `separators` for additional commit keys.

```svelte
<TagsInput bind:value={tags} ariaLabel="Retro tags" />
<TagsInput
	bind:value={labels}
	ariaLabel="Labels"
	validate={(label) => label.length <= 24}
	onInvalid={(label, reason) => console.log(label, reason)}
/>
```

`EmailInput` is a thin `TagsInput` preset for invite flows. It splits pasted addresses on commas, semicolons, whitespace, and newlines, lowercases them for storage, ignores duplicates, and rejects incomplete addresses. Invalid text stays in the input so the user can correct it; use `onInvalid` to surface the reason. Both components expose `id`, `describedBy`, `invalid`, and `disabled` for field composition.

`InlineEdit` edits a single string in place. The display is a button, and `editing` is bindable so a card menu or other external control can open the editor. Clicking the display opens it too. `placeholder` and `ariaLabel` are required; an empty value is allowed and falls back to the placeholder. `onValueChange` fires only when a changed value is committed.

```svelte
<InlineEdit
	bind:value={card.text}
	bind:editing={isEditing}
	placeholder="Add a card"
	ariaLabel="Card text"
	multiline
	onValueChange={(next) => saveCard(card.id, next)}
/>
```

Single-line mode saves on Enter. Multiline mode inserts a newline on Enter and saves on Cmd/Ctrl+Enter. Escape cancels, while blur commits unless focus moved into the inline actions or the edit was cancelled. The display and editor share the same text shell so switching modes does not shift the text.

## Structural exceptions

`Card` is a content shell rather than a combined interaction. It still uses one element, with optional `title` and `description` props plus `header`, `footer`, and body snippets. Layout shells such as `Sidebar` and `AppShell` follow the same rule: composition is allowed when the component is the layout. `Badge` is deliberately text-first: it takes a `label`, an optional icon, and an optional status dot rather than arbitrary children. Use the semantic `neutral`, `info`, `success`, `warning`, and `danger` variants for status; use `secondary`, `outline`, or `brand` for non-status labels.

## Code and Markdown

`CodeBlock` renders standalone highlighted code with copying. Set `showLineNumbers` for a numbered gutter, `highlightLines` for focused line ranges, and `wrap` for long lines.

`Markdown` renders sanitised GitHub-flavoured Markdown, including tables, links, images, and fenced code blocks. Fenced code is highlighted with `highlight.js`; raw HTML and scripts are removed. `ChatMarkdown` is the chat-labelled wrapper around the same renderer.

```svelte
<Markdown content={releaseNotes} />
```

`DiffViewer` renders a raw Git patch in unified or split mode. File headers show the change status and line totals; files and hunks can be collapsed. Renames, copies, binary files, mode-only changes, CRLF, and missing final newlines are handled. Syntax highlighting is inferred from each file path; pass `language` to override it. Set `showWhitespace` to reveal spaces and tabs as subtle muted markers.

```svelte
<DiffViewer {patch} view="split" />
```

`parsePatch` is exported for custom renderers and returns the normalised `DiffFile[]` model.

## Tables and dates

`Table` is the lightweight static counterpart to `DataTable`: typed columns, rows, an optional cell snippet, and an empty state without TanStack. `DataTable` uses TanStack Table for sorting. For large client-side row sets, opt into row virtualization with a fixed viewport height:

```svelte
<DataTable data={events} columns={eventColumns} virtualize={{ height: 320, rowHeight: 45 }} />
```

Virtualized tables render a sticky header and only the visible rows plus a small overscan buffer. `height` is the scroll viewport height in pixels. `rowHeight` is an initial estimate; rendered rows are measured, so rows can grow when their content wraps. Keep the full data set in the browser, and use server-side pagination or windowing when it cannot be loaded at once.

Set `selectionMode` to `single` or `multiple` to add a checkbox column. `selectedIds` is bindable and `onSelectionChange` receives the row ids. Pass `getRowId` so selection survives sorting and data refreshes; without it, row ids are the original data indexes.

Set `loading` while data is in flight. The table keeps its header and renders `loadingRows` skeleton rows, with `aria-busy` set on the table.

`Calendar` renders the date grid inline with single, multiple, and range selection, a floating month and year picker, a Today control, current-day indicator, and consistent rows across multiple months. `DatePicker` and `DateRangePicker` compose it for form surfaces; `TimePicker` keeps the segmented field and adds hour, minute, and optional second steppers in its popover.

## Trees and hierarchy

`TreeView` takes recursive `TreeNode[]` and supports controlled expansion, single or multiple selection, optional tri-state checkboxes, and native drag-and-drop. Pass `draggable` and `onMove`, then apply the move with the exported `moveTreeNode` helper. Dragging starts anywhere on a row, and node text selection is disabled. The `node` snippet receives the node plus its level, expansion, selection, and check state. `cascade={false}` makes checkbox changes independent.

## Media previews

`Lightbox` is a full-screen media viewer with an optional `trigger` button or controlled `bind:open` state. It accepts a typed `items` array of images, text, source files, and unsupported files, with previous/next navigation, a counter, captions, close-on-overlay, and focus restoration. The document name sits above the reader surface. Markdown text offers rendered Preview and raw Code tabs; source files render directly through `CodeBlock` with syntax highlighting. Items with `downloadUrl` get a header download action; unsupported files show a centred fallback and download button inside the lightbox.

`Attachment` is the generic chip for a single file, and `AttachmentList` composes chips with a shared lightbox. The whole chip opens the preview; the title is plain text and the remove control stays separate. `ChatAttachments` is a chat-labelled wrapper around `AttachmentList`. Text and source previews require `content`, while `href` supplies the download URL. `FileUpload` reads local text and source files and creates object URLs for previews and downloads. Source language detection covers common extensions and MIME types, including Markdown, JavaScript/TypeScript, Python, Rust, Go, Java, C/C++, C#, CSS, JSON, YAML, SQL, shell, HTML/XML, Dockerfile, and Makefile. `ChatAttachments` and `FileUpload` accept `preview={false}` to keep static chips.

## Application chrome

`Sidebar` takes typed groups of navigation items, supports a bindable `collapsed` state, and can render `header` and `footer` snippets. `AppShell` composes a sidebar, optional header, and scrollable content area for a full application frame.

## Patterns

`ConfirmDialog`, `EmptyState`, and `PageHeader` compose the smaller primitives for recurring page-level states.

- `ConfirmDialog` wraps the alert-dialog behaviour and a destructive confirm action. Use `confirmLabel`, `variant`, and `onConfirm` for irreversible decisions; the dialog closes after confirming.
- `EmptyState` handles no-data and zero-result states with an optional icon, description, and `action` snippet.
- `PageHeader` renders the page title, optional description, and `breadcrumb` and `actions` snippets. It keeps the responsive action layout consistent across pages.

## Chat and LLM surfaces

`Chat` is the batteries-included conversation component: typed messages, Markdown rendering, copy and feedback actions, and a composer with Enter-to-send, Shift+Enter, and stop-generation support. Use it when a consumer wants a complete chat surface with minimal wiring.

```svelte
<script lang="ts">
	import { Chat } from '@leap-online/jolt';

	let value = $state('');
	const messages = [
		{ id: '1', role: 'user' as const, content: 'Summarise the release.' },
		{ id: '2', role: 'assistant' as const, content: 'The release is ready.' },
	];
</script>

<Chat {messages} bind:value onSend={(message) => (value = message)} />
```

For custom surfaces, compose the primitives directly:

- `ChatViewport` handles scroll-to-bottom behaviour and a keyboard-focusable conversation log.
- `ChatMessage` renders role-aware rows with avatars, statuses, and message actions.
- `ChatComposer` provides the auto-growing input and send/stop controls. Use its `toolbar` snippet for model, effort, or attachment controls, and `onFiles` to accept files dropped onto the composer. `Chat` forwards both props to its composer.
- `ChatMarkdown` wraps the shared Markdown renderer for chat surfaces.
- `ChatToolCall` and `ChatReasoning` expose collapsible tool activity and thinking. `ChatToolCall` also supports `status="awaiting-approval"`: it renders a split Allow control, with a chevron menu for always-allow and optional custom allow options such as allowing for the current session. A separate ellipsis menu holds other actions, with Deny between it and the split control. All menus use the same entries as `DropdownMenu`. After a denial, set `status="denied"` to keep the decision visible on the tool call.
- `ChatSources` and `ChatSuggestions` cover citations and starter prompts.
- `ChatAttachments` renders generic attachment chips for messages and composer toolbars. Set `content` on Markdown, text, or source attachments so they can preview; `href` becomes the download URL.

Chat status indicators keep their visible label, and the user bubble inherits its foreground colour from the bubble rather than the page. Code inside a user bubble uses the bubble colours instead of the page code palette.

## Small primitives

`Spinner` provides an accessible loading indicator for async actions and chat states. `Loader` renders three animated dots in small, default, and large sizes; `ChatLoader` composes the small loader with a visible label. `Kbd` renders keyboard shortcut labels. `Avatar` accepts an optional `status` (`online`, `away`, `busy`, or `offline`) and renders an accessible presence dot; `AvatarGroup` passes the same fields through its items. `AvatarGroup` overlaps avatars, caps the visible count, and exposes an overflow count.

`CopyButton` copies a supplied string with the async clipboard API. It handles success, failure, and unavailable-clipboard states, keeps a labelled or icon-only appearance, and announces the result to screen readers. Use `copyLabel`, `copiedLabel`, `errorLabel`, and `unavailableLabel` for custom copy. `CodeBlock` uses it internally, and `ChatActions` shares the same clipboard helper.

`ReactionBar` renders a supplied set of emoji reactions as accessible toggle chips. Each reaction carries a stable `key`, an emoji, a required label, a count, and an optional active state. Toggling updates the count optimistically and emits the new array through `onReactionsChange`; `reactions` is bindable. The component does not include an emoji picker or add-reaction flow. Zero counts are hidden, and active chips use the brand tint.

```svelte
<ReactionBar
	bind:reactions={card.reactions}
	ariaLabel="Card reactions"
	onReactionsChange={(next) => saveReactions(card.id, next)}
/>
```

## Classes and accessibility

Every component accepts `class` for the outer element and named class props such as `contentClass`, `itemClass`, or `triggerClass` for internal parts. Prefer semantic tokens over hardcoded colours.

The prop surface is curated rather than inherited from the underlying HTML element. Presentational components such as Card, Alert, Avatar, and Skeleton expose only the props they actually use; use the class props for styling and keep arbitrary HTML attributes out of the component API.

Combined components cannot guess the field label. Use a field wrapper where one exists, pass `ariaLabel` on `Select` and `Combobox`, use the visible `label` prop on `Checkbox` and `Switch`, and use `ariaLabel` on `Tabs`. Dialog requires a `title`. Stories run axe with `error` level, so accessibility regressions fail the test suite.

Motion is always optional: transitions respect `prefers-reduced-motion`, and disclosure content animates with the height variables supplied by bits-ui.
