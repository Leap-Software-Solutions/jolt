# Component guidelines

Jolt components wrap bits-ui primitives, so consumers get the behaviour without the parts-and-portals boilerplate. The common case should be one import and one element.

## Combined by default

Most components own their trigger, portal, content, and focus management:

```svelte
<script lang="ts">
	import { Dialog, Select } from '@leap/jolt';

	let status = $state('active');
	let open = $state(false);
</script>

<Select
	items={[
		{ value: 'active', label: 'Active' },
		{ value: 'draft', label: 'Draft' },
	]}
	bind:value={status}
	ariaLabel="Status"
/>

<Dialog bind:open title="Delete asset" description="This cannot be undone.">
	<p>...</p>
</Dialog>
```

State is controlled with `bind:` props such as `bind:open`, `bind:value`, and `bind:checked`. Event callbacks (`onValueChange`, `onOpenChange`, `onCheckedChange`) remain available when you need to react to changes.

## Snippets

Content is customised with named snippets instead of exported parts. The names are consistent across components:

- `trigger` — render a trigger element with the props supplied by the primitive.
- `item` — render one item in a list, menu, or combobox.
- `selected` — render the selected value inside a trigger.
- `empty` — render the empty state for a list or search result.
- `header` / `footer` — render a content section.
- `content` — render the main panel or body.

```svelte
<Combobox
	items={engineers}
	bind:value
	getKey={(engineer) => engineer.id}
	getLabel={(engineer) => engineer.name}
	placeholder="Assign engineer"
	ariaLabel="Assign engineer"
>
	{#snippet item(engineer)}
		<span>{engineer.name}</span>
	{/snippet}

	{#snippet empty()}
		No engineers match that search.
	{/snippet}
</Combobox>
```

## Lists and item arrays

`Select`, `Combobox`, `MultiSelect`, `NavigationMenu`, `Menubar`, `DropdownMenu`, `ContextMenu`, `Tabs`, `Accordion`, `RadioGroup`, `ToggleGroup`, `Breadcrumb`, and `Pagination` take typed item arrays or configuration props. This keeps the markup small and makes keyboard navigation, typeahead, and selection state live in one place.

- `Select` items are `{ value, label, disabled? }`. Pass `getKey` when values are objects.
- `Combobox` takes your own data array plus `getKey` and `getLabel`.
- `MultiSelect` uses the same item array plus a bindable `values` array and renders selected items as removable chips.
- `ContextMenu` uses the same entry union as `DropdownMenu` and opens on the trigger's context-menu event.
- `NavigationMenu` items either provide a `content` snippet for a panel or an `href` for a direct link; `value` controls the open panel.
- `Menubar` takes typed menu entries in a horizontal bar; its menus support separators, groups, submenus, checkboxes, radio groups, shortcuts, and disabled items.
- `DropdownMenu` uses a discriminated union over `item`, `separator`, `group`, `submenu`, `checkbox`, and `radio`. Items with no `type` are regular actions.
- `Tabs` items are `{ value, label, icon?, disabled? }`; the `content` snippet receives the item.
- `Accordion` items are `{ value, title, content?, icon?, disabled? }`; the `trigger` and `content` snippets receive the item.
- `RadioGroup` items are `{ value, label, description?, icon?, disabled? }`.
- `ToggleGroup` items are `{ value, label?, ariaLabel?, icon?, disabled? }`.
- `Breadcrumb` items are `{ label, href?, icon?, current? }`; set `maxItems` to collapse the middle of long paths into an overflow menu.
- `Pagination` takes `count`, `perPage`, `page`, and `siblingCount`; page changes use `bind:page`.

Generic components are inferred at the call site:

```svelte
<Combobox
	items={engineers}
	bind:value
	getKey={(engineer) => engineer.id}
	getLabel={(engineer) => engineer.name}
	ariaLabel="Assign engineer"
/>
```

## Fields

The field wrappers combine a visible label, optional hint, error text, and the control's ARIA wiring:

```svelte
<script lang="ts">
	import { CheckboxField, SelectField, TextField } from '@leap/jolt';

	let name = $state('');
	let status = $state('active');
	let accepted = $state(false);
</script>

<TextField label="Full name" bind:value={name} required />
<SelectField label="Status" items={statuses} bind:value={status} />
<CheckboxField label="Accept the terms" bind:checked={accepted} />
```

`TextField`, `TextareaField`, `SelectField`, and `CheckboxField` generate their own ids. The error text becomes `role="alert"` and is connected to the control with `aria-describedby`; the control gets `aria-invalid` while the error is present. Prefer these wrappers over rebuilding label and description markup by hand.

## Structural exceptions

`Card` is a content shell rather than a combined interaction. It still uses one element, with optional `title` and `description` props plus `header`, `footer`, and body snippets. Layout shells such as `Sidebar` and `AppShell` follow the same rule: composition is allowed when the component is the layout.

## Application chrome

`Sidebar` takes typed groups of navigation items, supports a bindable `collapsed` state, and can render `header` and `footer` snippets. `AppShell` composes a sidebar, optional header, and scrollable content area for a full application frame.

## Patterns

`ConfirmDialog`, `EmptyState`, and `PageHeader` compose the smaller primitives for recurring page-level states.

- `ConfirmDialog` wraps the alert-dialog behaviour and a destructive confirm action. Use `confirmLabel`, `variant`, and `onConfirm` for irreversible decisions; the dialog closes after confirming.
- `EmptyState` handles no-data and zero-result states with an optional icon, description, and `action` snippet.
- `PageHeader` renders the page title, optional description, and `breadcrumb` and `actions` snippets. It keeps the responsive action layout consistent across pages.

## Classes and accessibility

Every component accepts `class` for the outer element and named class props such as `contentClass`, `itemClass`, or `triggerClass` for internal parts. Prefer semantic tokens over hardcoded colours.

The prop surface is curated rather than inherited from the underlying HTML element. Presentational components such as Card, Alert, Avatar, and Skeleton expose only the props they actually use; use the class props for styling and keep arbitrary HTML attributes out of the component API.

Combined components cannot guess the field label. Use a field wrapper where one exists, pass `ariaLabel` on `Select` and `Combobox`, use the visible `label` prop on `Checkbox` and `Switch`, and use `ariaLabel` on `Tabs`. Dialog requires a `title`. Stories run axe with `error` level, so accessibility regressions fail the test suite.

Motion is always optional: transitions respect `prefers-reduced-motion`, and disclosure content animates with the height variables supplied by bits-ui.
