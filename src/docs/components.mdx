# Component guidelines

Jolt components wrap bits-ui primitives, so consumers get the behaviour without the parts-and-portals boilerplate. The common case should be one import and one element.

## Combined by default

Most components own their trigger, portal, content, and focus management:

```svelte
<script lang="ts">
	import { Dialog, Select } from '@leap/jolt';

	let status = $state('active');
	let open = $state(false);
</script>

<Select
	items={[
		{ value: 'active', label: 'Active' },
		{ value: 'draft', label: 'Draft' },
	]}
	bind:value={status}
	ariaLabel="Status"
/>

<Dialog bind:open title="Delete asset" description="This cannot be undone.">
	<p>...</p>
</Dialog>
```

State is controlled with `bind:` props such as `bind:open`, `bind:value`, and `bind:checked`. Event callbacks (`onValueChange`, `onOpenChange`, `onCheckedChange`) remain available when you need to react to changes.

## Snippets

Content is customised with snippets instead of exported parts. Default body content uses `children`; named snippets are reserved for chrome and repeated items:

- `trigger` — render a trigger element with the props supplied by the primitive.
- `item` — render one item in a list, menu, or combobox.
- `selected` — render the selected value inside a trigger.
- `empty` — render the empty state for a list or search result.
- `header` / `footer` — render a content section.
- `children` — render the main body or panel content.
- `content` — render a tab or accordion item body.

```svelte
<Combobox
	items={engineers}
	bind:value
	getKey={(engineer) => engineer.id}
	getLabel={(engineer) => engineer.name}
	placeholder="Assign engineer"
	ariaLabel="Assign engineer"
>
	{#snippet item(engineer)}
		<span>{engineer.name}</span>
	{/snippet}

	{#snippet empty()}
		No engineers match that search.
	{/snippet}
</Combobox>
```

## Content model

Use a prop when the component owns a fixed piece of copy, `children` when the caller needs arbitrary composition, and typed arrays for repeatable data. Named snippets are for trigger, header, footer, empty state, and item renderers.

```svelte
<Badge label="Active" />

<Alert title="Could not save" description="Check your connection and try again." />

<Dialog title="Delete asset" description="This cannot be undone.">
	<p>Any content can go here.</p>
</Dialog>

<Tabs items={tabs} bind:value>
	{#snippet content(item)}
		<p>{item.label} panel</p>
	{/snippet}
</Tabs>
```

The current components follow this split:

- Fixed copy: `Badge`, `Alert`, `Card` header, `Dialog`, `Sheet`, `ConfirmDialog`, `PageHeader`, `EmptyState`, fields, `Checkbox`, `Switch`, and progress/slider labels.
- Arbitrary composition: `Button`, `Toggle`, `Label`, `ScrollArea`, `Card` body, dialog/sheet bodies, `HoverCard`, `Popover`, and `AppShell` content.
- Typed data: the list components below, plus `Select`, `Combobox`, `MultiSelect`, `SplitButton`, `Table`, `DataTable`, and `TreeView`.

`Popover` uses `children` for its content, matching Dialog, Sheet, and HoverCard. Tooltip keeps its `text` prop for the common case and an optional custom `content` snippet.

## Lists and item arrays

`Select`, `Combobox`, `MultiSelect`, `SplitButton`, `NavigationMenu`, `Menubar`, `DropdownMenu`, `ContextMenu`, `Tabs`, `Accordion`, `RadioGroup`, `ToggleGroup`, `Breadcrumb`, and `Pagination` take typed item arrays or configuration props. This keeps the markup small and makes keyboard navigation, typeahead, and selection state live in one place.

- `Select` items are `{ value, label, disabled? }`. Pass `getKey` when values are objects.
- `Combobox` takes your own data array plus `getKey` and `getLabel`.
- `MultiSelect` uses the same item array plus a bindable `values` array and renders selected items as removable chips.
- `ContextMenu` uses the same entry union as `DropdownMenu` and opens on the trigger's context-menu event.
- `NavigationMenu` items either provide a `content` snippet for a panel or an `href` for a direct link; `value` controls the open panel.
- `Menubar` takes typed menu entries in a horizontal bar; its menus support separators, groups, submenus, checkboxes, radio groups, shortcuts, and disabled items.
- `DropdownMenu` uses a discriminated union over `item`, `separator`, `group`, `submenu`, `checkbox`, and `radio`. Items with no `type` are regular actions.
- `Tabs` items are `{ value, label, icon?, disabled? }`; the `content` snippet receives the item.
- `Accordion` items are `{ value, title, content?, icon?, disabled? }`; the `trigger` and `content` snippets receive the item.
- `RadioGroup` items are `{ value, label, description?, icon?, disabled? }`.
- `ToggleGroup` items are `{ value, label?, ariaLabel?, icon?, disabled? }`.
- `SplitButton` takes a label, a primary action, and typed menu entries for the adjacent chevron menu.
- `Breadcrumb` items are `{ label, href?, icon?, current? }`; set `maxItems` to collapse the middle of long paths into an overflow menu.
- `Pagination` takes `count`, `perPage`, `page`, and `siblingCount`; page changes use `bind:page`.

Generic components are inferred at the call site:

```svelte
<Combobox
	items={engineers}
	bind:value
	getKey={(engineer) => engineer.id}
	getLabel={(engineer) => engineer.name}
	ariaLabel="Assign engineer"
/>
```

## Fields

The field wrappers combine a visible label, optional hint, error text, and the control's ARIA wiring:

```svelte
<script lang="ts">
	import { CheckboxField, SelectField, TextField } from '@leap/jolt';

	let name = $state('');
	let status = $state('active');
	let accepted = $state(false);
</script>

<TextField label="Full name" bind:value={name} required />
<SelectField label="Status" items={statuses} bind:value={status} />
<CheckboxField label="Accept the terms" bind:checked={accepted} />
```

`TextField`, `TextareaField`, `SelectField`, and `CheckboxField` generate their own ids. The error text becomes `role="alert"` and is connected to the control with `aria-describedby`; the control gets `aria-invalid` while the error is present. Prefer these wrappers over rebuilding label and description markup by hand.

`FileUpload` handles drag-and-drop selection, file size validation, and removable file chips. It is a regular form control, not a chat-specific component.

## Structural exceptions

`Card` is a content shell rather than a combined interaction. It still uses one element, with optional `title` and `description` props plus `header`, `footer`, and body snippets. Layout shells such as `Sidebar` and `AppShell` follow the same rule: composition is allowed when the component is the layout. `Badge` is deliberately text-only: it takes a `label` and an optional icon rather than arbitrary children.

## Tables and dates

`Table` is the lightweight static counterpart to `DataTable`: typed columns, rows, an optional cell snippet, and an empty state without TanStack. `Calendar` renders the date grid inline with single, multiple, and range selection, a floating month and year picker, a Today control, current-day indicator, and consistent rows across multiple months. `DatePicker` and `DateRangePicker` compose it for form surfaces; `TimePicker` keeps the segmented field and adds hour, minute, and optional second steppers in its popover.

## Trees and hierarchy

`TreeView` takes recursive `TreeNode[]` and supports controlled expansion, single or multiple selection, optional tri-state checkboxes, and native drag-and-drop. Pass `draggable` and `onMove`, then apply the move with the exported `moveTreeNode` helper. Dragging starts anywhere on a row, and node text selection is disabled. The `node` snippet receives the node plus its level, expansion, selection, and check state. `cascade={false}` makes checkbox changes independent.

## Media previews

`ImageLightbox` is a full-screen image viewer with an optional `trigger` button or controlled `bind:open` state. It provides previous/next navigation, a counter, captions, close-on-overlay, and focus restoration. `ChatAttachments` opens it for image attachments that provide `href`, `previewSrc`, or `thumbnailSrc`; `FileUpload` creates and revokes object URLs for selected local image files. Both accept `preview={false}` to keep static attachment chips and file rows.

## Application chrome

`Sidebar` takes typed groups of navigation items, supports a bindable `collapsed` state, and can render `header` and `footer` snippets. `AppShell` composes a sidebar, optional header, and scrollable content area for a full application frame.

## Patterns

`ConfirmDialog`, `EmptyState`, and `PageHeader` compose the smaller primitives for recurring page-level states.

- `ConfirmDialog` wraps the alert-dialog behaviour and a destructive confirm action. Use `confirmLabel`, `variant`, and `onConfirm` for irreversible decisions; the dialog closes after confirming.
- `EmptyState` handles no-data and zero-result states with an optional icon, description, and `action` snippet.
- `PageHeader` renders the page title, optional description, and `breadcrumb` and `actions` snippets. It keeps the responsive action layout consistent across pages.

## Chat and LLM surfaces

`Chat` is the batteries-included conversation component: typed messages, Markdown rendering, copy and feedback actions, and a composer with Enter-to-send, Shift+Enter, and stop-generation support. Use it when a consumer wants a complete chat surface with minimal wiring.

```svelte
<script lang="ts">
	import { Chat } from '@leap/jolt';

	let value = $state('');
	const messages = [
		{ id: '1', role: 'user' as const, content: 'Summarise the release.' },
		{ id: '2', role: 'assistant' as const, content: 'The release is ready.' },
	];
</script>

<Chat {messages} bind:value onSend={(message) => (value = message)} />
```

For custom surfaces, compose the primitives directly:

- `ChatViewport` handles scroll-to-bottom behaviour and a keyboard-focusable conversation log.
- `ChatMessage` renders role-aware rows with avatars, statuses, and message actions.
- `ChatComposer` provides the auto-growing input and send/stop controls. Use its `toolbar` snippet for model, effort, or attachment controls, and `onFiles` to accept files dropped onto the composer. `Chat` forwards both props to its composer.
- `ChatMarkdown` sanitises assistant Markdown and highlights fenced code blocks.
- `CodeBlock` renders standalone highlighted code with copying.
- `ChatToolCall` and `ChatReasoning` expose collapsible tool activity and thinking. `ChatToolCall` also supports `status="awaiting-approval"`: it renders a split Allow control, with a chevron menu for always-allow and optional custom allow options such as allowing for the current session. A separate ellipsis menu holds other actions, with Deny between it and the split control. All menus use the same entries as `DropdownMenu`. After a denial, set `status="denied"` to keep the decision visible on the tool call.
- `ChatSources` and `ChatSuggestions` cover citations and starter prompts.
- `ChatAttachments` renders file chips for messages and composer toolbars.

Markdown is sanitised with `sanitize-html`; code highlighting uses `highlight.js`. Both are runtime dependencies of the package, so consumers do not need to add a renderer themselves. Chat status indicators keep their visible label, and the user bubble inherits its foreground colour from the bubble rather than the page. Code inside a user bubble uses the bubble colours instead of the page code palette.

## Small primitives

`Spinner` provides an accessible loading indicator for async actions and chat states. `Loader` renders three animated dots in small, default, and large sizes; `ChatLoader` composes the small loader with a visible label. `Kbd` renders keyboard shortcut labels. `AvatarGroup` overlaps avatars, caps the visible count, and exposes an overflow count.

## Classes and accessibility

Every component accepts `class` for the outer element and named class props such as `contentClass`, `itemClass`, or `triggerClass` for internal parts. Prefer semantic tokens over hardcoded colours.

The prop surface is curated rather than inherited from the underlying HTML element. Presentational components such as Card, Alert, Avatar, and Skeleton expose only the props they actually use; use the class props for styling and keep arbitrary HTML attributes out of the component API.

Combined components cannot guess the field label. Use a field wrapper where one exists, pass `ariaLabel` on `Select` and `Combobox`, use the visible `label` prop on `Checkbox` and `Switch`, and use `ariaLabel` on `Tabs`. Dialog requires a `title`. Stories run axe with `error` level, so accessibility regressions fail the test suite.

Motion is always optional: transitions respect `prefers-reduced-motion`, and disclosure content animates with the height variables supplied by bits-ui.
